# TASK ARCHIVE: nap-ack

## SUMMARY

Successful `summem nap` prints `Saved.` then either the next fold prompt or `Nothing left to compress.` The `ENTRY_CHARS` ratchet still does not ACK. `fold_request` stays a prompt builder: idle is printed only on the `nap` arm when that helper returns empty. Merged as [PR #70](https://github.com/Texarkanine/SumMem/pull/70). QA passed. `tox` 367 passed, 1 skipped, on py311–py314.

## REQUIREMENTS

From the project brief:

- Successful `nap` prints `Saved.` then, if a fold is still owed, the existing fold prompt (including the remaining-count line when it applies).
- Successful `nap` with no further fold prints `Saved.` then `Nothing left to compress.`
- A `note` that needs a nap still prints `Saved.` plus the fold prompt only.
- Over-long `note` and `nap` exit 1, stderr only, no `Saved.`
- Retarget existing nap-stdout tests; do not delete them.
- Do not assemble ACK or idle inside `fold_request`. Do not change OptMem. Do not put the idle line on a successful `note` that needs no nap.

## IMPLEMENTATION

On `main`'s successful `nap` path, after `with_store_lock`, print `Saved.\n`; if `fold_request` returned text, a blank line then that text; else a blank line then `Nothing left to compress.\n`. Spacing matches `note`. Reject paths are unchanged (`require_entry` still returns 1 before lock).

Idle means no next fold request, including an over-budget view with no equal-grain pair. It does not mean “at `WAKE_LINES`.”

`fold_request` is unchanged. The four-line `nap` block duplicates three lines of the `note` block; `emit_result` was deferred (Preflight Advisory 4).
